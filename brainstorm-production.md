# Takt: от ремесленного монтажа к продакшну — вводная для нового обсуждения

## Что за проект

**Takt** — скилл Claude Code для съёмки демо-роликов по веб-интерфейсам.
Публичный репозиторий: `github.com/Braidner/takt`, локально `~/IdeaProjects/fesb-demo`.
Сайт-презентация: `braidner.github.io/takt` (GitHub Pages из `docs/`).

Устройство: агент поднимает локальную студию (`takt serve`, страница на :4173), садится
на длинный опрос (`takt poll`) и работает по событиям от человека. Данные (проекты,
цели, голоса) живут в `$TAKT_HOME` (по умолчанию `~/takt`), отдельно от кода скилла.

**Три уровня знания:** код скилла → цель съёмки (система, про которую снимают: адрес,
вход, селекторы, заметки) → проект (один ролик: сценарий, дубли, замечания, озвучка).

**Конвейер сейчас:**
```
takt shoot   Playwright headless проходит сценарий, пишет webm + телеметрию
             (события-титры, координаты кликов)
takt build   webm → mp4 мастер, обрезка входа в систему
takt edit    монтаж: камера, курсор, титры, виньетка, заставка, звук → movie-cut.mp4
takt highlight  короткая версия из лучших моментов, есть --vertical 9:16
```

Всё на **ffmpeg**. Remotion лежит в `optionalDependencies` и в монтаже не используется.

Ключевые файлы: `studio/shoot.mjs`, `studio/edit.mjs`, `studio/highlight.mjs`,
`studio/titles.mjs` (титры рисует Playwright в PNG с альфой), `studio/sound.mjs`
(музыка синтезируется через ffmpeg lavfi).

## Что уже работает

- камера наводится на действия по **координатам из телеметрии**, а не по эвристике
  «где мигнуло» (мы сами кликали — знаем точно куда); есть `--drift` для витрин;
- курсор рисуется монтажом (headless-съёмка его не пишет);
- титры — PNG из браузера, брендовая типографика, правка без пересъёмки;
- звук синтезируется: дрон-подложка, щелчки на действиях, sidechain-пригрушение;
- хайлайты отбираются по смыслу (действие важнее смены экрана), не по движению;
- в студии: сценарий с перетаскиванием шагов, дорожки таймлайна с кликами и
  перетаскиванием меток, замечания по таймкодам с разбором по стоимости,
  панель окружения, переключатель версий ролика, два языка.

Примеры результата (свежие, в репозитории): `$TAKT_HOME/projects/mc-медиа/movie-cut.mp4`
(реклама медиатеки Mission Control, 56 с), `movie-short.mp4` (20 с),
`movie-short-vertical.mp4` (15 с).

## Проблема: результат ремесленный, а не продакшн

Хозяин проекта посмотрел ролики и сказал прямо: «топорно». Это справедливо. Мой
диагноз — не косметика, а несколько системных причин.

**1. Исходник меньше цели.** Пишем 1440×810, монтируем в 1920×1080. Любой наезд —
апскейл поверх апскейла, отсюда мыло на тексте. Профессионалы снимают в 2× и
даунскейлят. Это фундамент: пока он не исправлен, остальное косметика.

**2. Нет ритма.** Сцены одинаковой длины (6-8 с), титры появляются механически в
начале сцены, склейки не связаны ни с чем. Настоящий монтаж строится на ритме:
короткие планы чередуются с длинными, склейки попадают на доли музыки.

**3. Музыка не задаёт темп.** Синтезированный дрон без BPM — под него нельзя резать.
Реклама режется под биты; у нас звук просто «есть».

**4. Титры не рекламные.** Плашка внизу — язык туториала. В рекламе титр крупный, по
центру или с акцентом, с анимацией входа (маска, вылет), а не с fade.

**5. Курсор телепортируется.** Он возникает в точке и гаснет. Живой курсор движется
по траектории с ускорением и замедлением.

**6. Экран снят «как есть».** Нет рамки окна браузера, тени, фона. Профессиональные
демо ставят запись в мокап на градиент — это половина ощущения «студийности».

**7. Камера едет линейно** между планами, без кривых ease-in-out и без микродвижения
внутри плана.

**8. Загрузка попадает в кадр.** Сценарий ждёт таймаутом, а не реальным контентом:
в кадр попадают скелетоны и пустые витрины.

**9. Одна композиция на всё.** Всегда полный экран, никогда — крупный план элемента,
разрезка на два кадра, наложение.

**Главное подозрение: ffmpeg — не монтажный инструмент.** Мы упёрлись в его потолок.
Всё сложное (анимация титров, кривые камеры, мокап-рамки, синхронизация с музыкой,
композитинг) в нём делается через боль и выражения в строках, а отлаживается только
по готовому файлу. За эту сессию три дефекта были **молчаливыми**: наезда камеры не
было вовсе (`crop` вычисляет размер один раз), звук обрезал ролик с 83 до 56 с
(`sidechaincompress` кончается по кратчайшему входу), титры не появлялись (PNG без
`-loop` живёт один кадр). Ни один не дал ошибки.

## О чём хочу поговорить в новом чате

Не «сделай красиво», а выбрать архитектуру продакшна. Варианты, которые вижу:

**A. Вернуться к Remotion** (React + анимация покадрово). Даёт настоящие кривые,
spring-анимацию титров, мокап-рамки как компоненты, синхронизацию с музыкой,
предпросмотр в браузере. Минусы: платная лицензия от 4 человек, тяжелее, надо
переписать монтаж целиком.

**B. Остаться на ffmpeg, но поднять качество основ:** снимать в 2880×1620,
мокап-рамка и фон как PNG-накладки, ритм по BPM синтезированной музыки,
анимация титров кадрами (рендерить последовательность PNG из браузера).

**C. Гибрид:** композитинг и анимацию делать браузером (Playwright рендерит кадры
целиком — фон, рамка, титры, курсор), а ffmpeg оставить только склейкой и звуком.
По сути свой мини-Remotion без лицензии.

**D. Что-то ещё** — например, готовые инструменты вроде Screen Studio (macOS,
платный, делает ровно это), Motion Canvas, Rive.

Мои вопросы к обсуждению:
1. Какая архитектура правильная с учётом того, что Takt — открытый скилл, который
   ставят чужие люди (лицензии и вес установки важны)?
2. Что даст наибольший скачок качества за наименьшую работу — вероятно, разрешение
   съёмки и мокап-рамка, но хочу проверить это рассуждением, а не на глаз.
3. Как сделать ритм: генерировать музыку с темпом и резать по долям, или наоборот —
   монтировать по смыслу, а музыку подгонять?
4. Нужен ли вообще «универсальный» монтаж, или правильнее пресеты жанров
   (демо-туториал / реклама продукта / сторис), у каждого свои правила?

**Формат обсуждения:** сначала думаем и спорим, к коду переходим, когда решим
архитектуру. Мне важнее правильный выбор, чем быстрый патч.
