## Где мы

Ветка `production-pipeline`, 25 коммитов от `main`, всё запушено. 78 тестов, все зелёные,
`npm test`. Стадия 1 из четырёх закрыта и проверена на живом стенде.

**Главный документ — `specs/2026-08-01-production-design.md`** (редакция вторая). Ядро:
**снимаем состояния, а не поток**. Страница снимается целиком одним кадром в 2×
(`page.screenshot fullPage` при `deviceScaleFactor: 2`, ~224 мс на 2880×8278), а
прокрутка, наезд и удержание СОБИРАЮТСЯ композицией — кадр вычисляется из номера, как в
Remotion. Дропнутых кадров не существует по построению.

В спеке есть раздел «Почему первая редакция была неверной» с таблицей замеров — прочитай
его, чтобы не предложить заново ни поток в 2× (6,2 к/с на живой странице), ни захват
экрана ОС (работает, но отвергнут: headful, разрешения, три платформы).

## Что сделано (стадия 1)

`studio/lib/` — восемь модулей, логика вынесена из shoot.mjs, всё под тестами:

| Модуль | Что делает |
|---|---|
| `settle.mjs` | ожидание по содержимому: признак + сеть (грация 1,5 с) + неподвижность картинки |
| `sticky.mjs` | липкие слои: поиск, скрытие `visibility`, край по растянутости |
| `state.mjs` | `captureState`: успокоение → догрузка ленивых → слой → тело → якоря |
| `inspect.mjs` | `checkStates` + старые проверки потока |
| `frame-signature.mjs` | сигнатура кадра 32×18, мера различия |
| `scroll.mjs` | плавная прокрутка (для live-планов и догрузки) |
| `anchors.mjs`, `recorder.mjs` | остались для live-планов |

`studio/shoot.mjs` — оркестратор. На каждый шаг: действия → `captureState` → в манифест.
Итог съёмки — `states.json` проекта: манифест состояний с относительными путями,
липкими слоями, якорями и замечаниями. `recordVideo` включается только если в сценарии
есть шаг с `mode: 'live'`.

Прогон mc-медиа: 7 состояний, 0 замечаний, 22,5 МБ. Все якоря найдены, включая
`button:has-text("БОЕВИКИ")`, который в записи «не попадал в кадр», — состояние это вся
страница, зум в пустоту невозможен по устройству.

## Известное сломанное (намеренно)

**`takt build` и `takt edit` не работают для статичных проектов** — у них нет видеофайла.
Спека обещала рабочий конвейер на каждой границе стадий; здесь обещание нарушено и
записано в коммит 9752be0. Стадия 2 это чинит: композиция и есть новый монтаж.

## Стадия 2 — что делать (следующая работа)

Композиция: чистая функция `render(film, frame) → DOM`, два привода (скраббер студии,
покадровый цикл). Собирает из состояний: фон, мокап-рамка, панорама по телу снимка,
липкий слой поверх (неподвижно, по краю из `sticky[].edge`), курсор по траектории,
титры, виньетка. За ffmpeg — только кодирование и звук (`sound.mjs` не трогать).

**Рабочий прототип уже есть: `remotion-mc/pan.tsx`** — панорама по снимку с мокап-рамкой
и титрами, рендерится через `remotion-mc/render-pan.mjs` за 11 с. Из него переезжают
кривые и layout, но САМ Remotion в поставку не входит: спека требует свой привод
(24,9 мс/кадр замерено), Remotion выводится из поставки в этой же стадии
(`optionalDependencies`, `doctor`, `registry`, README, `src/`).

Хайлайты пересобираются той же композицией. Частота ролика: все планы статичные — 30 к/с,
есть живой — весь ролик 25 к/с (правило в спеке).

Порядок, который советую: спека-план стадии 2 → композиция+скраббер → свой покадровый
привод → сборка movie.mp4 из states.json → пересъёмка и пересборка mc-медиа как дымовой
тест → вывод Remotion из поставки.

## Грабли, оплаченные этой сессией — не наступать снова

1. **Сырой CDP-цикл нельзя гонять параллельно с действиями Playwright** на той же
   странице: конкуренция за снимки вешает захват намертво и молча. Дважды воспроизведено.
   Всё через API Playwright.
2. **`document.querySelector` не понимает селекторы Playwright** (`text=…`,
   `:has-text()`) — бросает, а общий catch молчит. Только локаторы.
3. **Замеры на синтетике врут**: 28,9 мс/кадр на пустой странице против 59,2 на живой.
   Мерить только на стенде.
4. **`networkidle` не наступает** у приложений с живыми соединениями — в `settle.mjs`
   уже грация, не делать сеть обязательным условием.
5. **У async `execFile` нет опции `input`** — молча игнорируется, ffmpeg виснет на stdin.
   В `frame-signature.mjs` уже spawn.
6. **`recordVideo.size` не масштабирует** — кладёт страницу в CSS-пикселях в угол
   большого холста, остальное серая заливка.
7. Разъезд шкал времени записи и телеметрии — у состояний его нет, но если трогаешь
   live-путь, помни: разметка по часам съёмки, длительность записи считает кодировщик.

## Рабочие правила (от хозяина проекта)

TDD (тесты вперёд для чистых функций), KISS, DRY, для фронта UX. Коммит на задачу,
пуш после задач. Комментарии и коммиты по-русски, в стиле репозитория: почему, а не что.
Никаких новых зависимостей без крайней нужды. Отчёты и образцы — в телеграм через
`~/.claude/skills/telegram/send.sh file <путь> "подпись"` (настроен).
