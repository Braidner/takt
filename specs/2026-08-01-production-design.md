# Продакшн: раскадровка, съёмка без брака, композиция в браузере

Дата: 2026-08-01. Статус: утверждено.

## Задача

Ролики выходят ремесленными. Хозяин проекта назвал три дефекта: дёрганый экран,
обновления страницы в кадре, наезды камеры в пустоту. Разбор телеметрии проекта
`mc-медиа` подтвердил все три и вскрыл общую причину.

**Зум в пустоту.** Третье действие записано как `x=177, y=3673` при высоте кадра 810.
Координата снимается `boundingBox()` до клика, а Playwright перед кликом сам прокручивает
страницу к элементу — записана позиция до прокрутки. Монтаж упирает такую цель в нижний
край кадра и наезжает туда, где уже другой экран. Курсор для этого действия рисуется на
y≈4900, за пределами кадра, и не появляется вовсе. Ошибки не было.

**Обновления страницы в кадре.** Сценарий ждёт часами, а не содержимым: `{"goto":"media"},
{"wait":5000}`, затем `{"click":"Дискавери"},{"wait":4500}`. Поле `expect` в шагах есть, но
проверяется после паузы и не управляет ею.

**Дёрганый экран.** Три слоя: прокрутка сделана `press: PageDown` — телепорт за один кадр;
запись идёт 25 к/с, монтаж тянет её до 30 дублированием; VP8 на 505–716 кбит/с (замер по
семи дублям) рассыпается на движении.

**Общая причина.** На 52 секунды ролика приходится три действия и семь титров, а
длительность каждой сцены назначена человеком числом 6–8. Камере нечего показывать в
четырёх сценах из семи, поэтому включается дрейф к произвольным третям кадра. Плоский
список шагов с ручными длительностями не оставляет места драматургии.

Отдельно: ffmpeg не может быть компоновщиком. Три дефекта прошлой сессии были молчаливыми
(`crop` вычисляет размер один раз, `sidechaincompress` кончается по кратчайшему входу, PNG
без `-loop` живёт один кадр) — граф фильтров это поток, спросить у него «как выглядит кадр
847» нельзя, поэтому такие ошибки не ловятся ничем, кроме просмотра готового файла.

## Решения, принятые на интервью

| Вопрос | Решение |
|---|---|
| Эталон качества | Продуктовое демо в мокапе (Screen Studio, Arc, Raycast): 4–8 с на план, живой курсор, наезды к месту действия, музыка фоном без битов. Монтаж по смыслу, не под долю |
| Место человека | Автомат плюс правка планов после съёмки. Раскадровка — данные, которые видно и можно двигать; пересборка быстрая |
| Сцена без действия | Управляемая плавная прокрутка как приём: страница едет ровно, камера стоит |
| Приёмка | Предотвращение — основная стратегия, автопроверки — страховка. Контактный лист не делаем |
| Кто рисует кадр | Композиция — портируемая функция кадра, привод свой. Всё MIT, Remotion в поставку не входит |
| Эффекты | Четыре семейства: камера, наложения, темп, склейки |
| Точки контроля | Три до съёмки: разведка → сюжет → раскадровка. Четвёртая — правка после съёмки |
| Объём | Весь флоу одной спекой, со стадиями внутри и рабочим конвейером на каждой границе |

## Модель данных

Три уровня знания сохраняются: **код скилла → цель съёмки → проект**. Внутри проекта
появляется цепочка, где каждое звено — файл в `$TAKT_HOME/projects/<id>/`.

```
prompt.txt        что попросил человек — исходник для перегенерации на любом шаге
recon.json        срез разведки под этот промпт          ← точка контроля 1
story.md          сюжет прозой                            ← точка контроля 2
storyboard.json   раскадровка: массив планов              ← точка контроля 3
take.json         телеметрия дубля: планы, треки якорей, проверки
take.mp4          мастер записи
film.json         то, что рендерится, после правок        ← точка контроля 4
movie.mp4         готовый ролик
```

### Разведка

Агент проходит интерфейс и раскладывает добычу по сроку жизни. Долгоживущее — в цель
съёмки (`targets/<slug>/target.json` и `target.md`): разделы и адреса, селекторы, признаки
догруженного экрана, время загрузки, что трогать нельзя. Срез под конкретный промпт —
в `recon.json` проекта. Правки человека в точке контроля 1 дописываются **и в цель тоже**,
иначе следующий ролик про тот же сайт начнёт с нуля.

### Сюжет

`story.md` — проза. Что показываем, в каком порядке, зачем зрителю, чем заканчиваем.
Пишет сценарист. **Намеренно без действий и селекторов:** как только в текст попадают
`click` и `wait`, драматургия исчезает — именно это и произошло с текущими сценариями.

### План

Центральная сущность раскадровки:

```json
{
  "id": "s4",
  "intent": "поиск находит за пару букв",
  "screen": { "route": "/discover", "waitFor": "text=В тренде сейчас" },
  "action": { "kind": "type", "selector": "input[placeholder*=\"Поиск\"]", "text": "одиссея" },
  "title": { "text": "Нашлось за пару букв", "style": "lower" },
  "effects": ["e11", "e12"],
  "duration": { "source": "derived", "seconds": 5.2 }
}
```

`action.kind` — закрытый список: `click`, `type`, `scroll`, `hold`, `goto`.

**Длительность выводится, а не назначается:**

```
duration = lead + act + hold

lead  подводка камеры: 0.6 с, если камера двигается, иначе 0
act   click  0.2 с
      type   длина текста / 12 знаков в секунду
      scroll дистанция / скорость (по умолчанию 600 px/с, параметр плана)
      hold   action.seconds — задаётся явно, это и есть смысл такого плана
      goto   0 (время загрузки не считается: оно вырезается, см. «Съёмка»)
hold  удержание результата: 2.6 с по умолчанию
```

**Границы плана: не короче 3,5 с и не длиннее 9 с.** Короткий план не успевает прочитаться
и сливается с соседним; длинный тормозит ролик. Если вывод дал меньше — увеличивается
`hold`. Если больше — режиссёр обязан разбить план на два, а не оставлять как есть.
Границы взяты из выбранного эталона: продуктовое демо держит 4–8 секунд на план.

До съёмки `hold` — оценка. После съёмки он уточняется по факту: берётся момент, когда
экран реально стал стабильным (см. «Ожидание по содержимому»). `storyboard.json` хранит
оценку, `film.json` — факт. Человек может переопределить любое значение — тогда поле
помечается `"source": "manual"` и пересчётом не затирается.

### Эффект

Одна типизированная сущность, четыре семейства:

```json
{
  "id": "e11",
  "kind": "camera",
  "at": { "from": 29.0, "to": 33.5 },
  "anchor": "input[placeholder*=\"Поиск\"]",
  "params": { "move": "push", "depth": 1.26 },
  "source": "auto"
}
```

| kind | params |
|---|---|
| `camera` | `move`: `push` \| `pull` \| `drift` \| `closeup`; `depth` |
| `overlay` | `what`: `spotlight` \| `arrow` \| `callout` \| `blur`; `text` для `callout` |
| `tempo` | `rate`: 0.5 замедление, 4 ускорение, 0 стоп-кадр |
| `transition` | `style`: `cut` \| `dissolve` \| `slide`; `duration` |

**Эффект целится в селектор, а не в координату.** Это устраняет «зум в пустоту» по
устройству, а не заплаткой.

### Трек якоря

Съёмка отдаёт не «клик был в точке», а положение элемента в кадре во времени:

```json
"anchors": [
  { "selector": "input[placeholder*=\"Поиск\"]",
    "rects": [ { "t": 29.0, "x": 76, "y": 622, "w": 1364, "h": 42 }, … ] }
]
```

Прямоугольники снимаются **после** авто-прокрутки Playwright, а не до. Камера следит за
треком. Если элемент уехал за пределы кадра, трека в этот момент нет: эффект не строится,
а автопроверка пишет «план 6: цель вне кадра». Промахнуться нечем.

Треки не зависят от новой модели плана и появляются уже на стадии 1: до перехода на
раскадровку они снимаются по селекторам, которые и так есть в шагах `scenario.json`
(`click`, `type`). На стадии 3 к ним добавляются якоря эффектов.

### Комментарии

Комментарий на плане или эффекте — **вход перегенерации, а не пометка на полях**. Написали
«слишком долго висит пустой экран», нажали «пересобрать» — режиссёр перечитывает
комментарии вместе с сюжетом и выдаёт новую раскадровку.

## Флоу и точки контроля

Три гейта до съёмки, четвёртый после. Каждый — экран студии: посмотреть, поправить,
прокомментировать, перегенерировать, утвердить.

Перегенерация на любом гейте **помечает нижележащее устаревшим, но не удаляет**. Изменили
сюжет — раскадровка получает метку «собрана по старому сюжету». Молча стирать чужую работу
нельзя: человек мог править её руками час назад.

Гейт можно проскакивать: на проекте флаг `gates: false`. Логики доверия и оценки
уверенности нет намеренно — здесь простота дороже умности.

## Съёмка

**Запись.** CDP-скринкаст при `deviceScaleFactor: 2`, 30 к/с, JPEG q92 → x264 crf 16.
Реализация уже существует в `capture/lib/recorder.mjs` и возвращается в строй. Уходят
разом низкое разрешение, VP8 на 600 кбит/с и дублирование кадров из 25 в 30.

Замер, обосновывающий выбор: `deviceScaleFactor: 2` без явного `recordVideo.size` не меняет
разрешение видео (остаётся 1440×810). Поднятие вьюпорта до 2880 меняет вёрстку и делает
текст мельче — это ошибка. SSIM по области с мелким текстом: 0,971 у честного 2× против
0,923 у растянутого 1×.

**Ожидание по содержимому.** Три условия вместо `wait: N`: выполнен `waitFor` плана,
сетевой покой, и картинка стабильна — два снимка с интервалом 250 мс различаются меньше
чем на 0,5% пикселей. `wait` как приём сценария исчезает.

Время между началом плана и выполнением всех трёх условий — это **загрузка**, и она
вырезается из мастера: в кадр попадает только готовый экран. Именно поэтому `goto`
не добавляет длительности плану.

**Прокрутка.** Драйвер в странице на `requestAnimationFrame`: постоянная скорость с
разгоном и торможением, дистанция и скорость — параметры плана. `PageDown` не используется.

**Треки якорей.** Во время плана раз в 100 мс снимаются прямоугольники элементов, на
которые ссылаются действие плана и его эффекты.

**Автопроверки дубля.** Отчёт по планам, а не по секундам:

1. **Загрузка в кадре** — определяется по DOM во время съёмки, а не анализом картинки:
   записываются интервалы, когда условия готовности ещё не выполнены, но кадры уже пишутся.
   Это надёжнее любой эвристики по пикселям.
2. **Скачок содержимого** — разница соседних кадров больше 35% пикселей вне запланированной
   склейки. Порог хранится в цели съёмки и настраивается: у плотных интерфейсов легитимная
   смена раздела меняет меньше половины кадра, у полноэкранных витрин — почти всё.
3. **Якорь вне кадра** — из трека.
4. **Потери кадров** — интервалы между кадрами скринкаста больше 1,5 периода.

## Композиция и рендер

Композиция — чистая функция `render(film, frame) → DOM`. Один модуль, два привода:
скраббер студии для предпросмотра и покадровый цикл для вывода. Предпросмотр и вывод не
могут разойтись, потому что это один код.

Кадр состоит из: фон, мокап-рамка, кадр записи с трансформом камеры, курсор по траектории,
наложения, титры, виньетка.

Рендер: разложить дубль в кадры одной командой ffmpeg → цикл по кадрам → ffmpeg собирает
mp4 и сводит звук. За ffmpeg остаётся кодирование, склейка и звук — то, в чём он хорош.
Ни одного выражения от времени.

Замер, обосновывающий выполнимость: композиция с тенями, блюром и трансформами снимается
через CDP `Page.captureScreenshot` за 24,9 мс на кадр — 45 секунд на минуту ролика в один
поток, около двенадцати в четыре вкладки. Remotion на той же композиции даёт 19,6 мс; вся
разница объясняется тем, что он не пишет кадры на диск.

**Мокап-рамка требует 2×-съёмки.** Рамка означает, что запись уменьшается и вписывается
внутрь кадра; при исходнике 1440p это дало бы апскейл при наезде. Мокап без 2× сделает
хуже, чем сейчас.

Эффекты: четыре вида, закрытый список, каждый — функция состояния. Ни плагинов, ни
универсального движка.

## Студия

Дорожки группируются, чтобы восемь штук не превратились в кашу:

```
Планы          сегменты с названиями, перетаскивание границ
Эффекты        свёрнутая группа: камера · наложения · темп · склейки
Звук
Замечания
```

Скраббер — главный инструмент: ролик смотрится без рендера. Клик по эффекту ставит плейхед
на его начало. Правка параметра видна сразу. Пересборка — секунды, потому что трогается
только `film.json`, съёмка не запускается.

Интерфейс следует существующей системе студии: те же токены, шрифты и типографика.
Обязательны клавиатурная навигация, контраст не ниже 4.5:1 и `prefers-reduced-motion`.

## Принципы работы

**TDD.** Тесты вперёд там, где есть чистая функция: вывод длительности плана, разрешение
якоря в цель камеры, четыре автопроверки, кривые движения, кадр композиции. Последнее —
главное приобретение: `render(film, 847) → PNG → сравнение с эталоном` делает видео
тестируемым покадрово. Три молчаливых дефекта прошлой сессии такой тест не пережили бы.
Тесты на «браузер запустился» не пишем.

Фикстуры: короткий записанный дубль в репозитории, чтобы тесты не требовали живого стенда.

**KISS.** Закрытый список эффектов и действий. Нет плагинов, нет универсального движка
таймлайна, нет логики доверия у гейтов.

**DRY.** Одна композиция на предпросмотр и рендер. Одно место, где считается длительность.
Одно место, где резолвится якорь.

**UX.** Скраббер вместо рендера для просмотра, мгновенная обратная связь на правку,
существующая система студии, доступность как требование, а не пожелание.

## Стадии

На каждой границе конвейер рабочий, и `mc-медиа` пересниматься целиком — это и есть
проверка, что стало лучше.

1. **Съёмка без брака.** Рекордер 2×/30 к/с, ожидание по содержимому, плавная прокрутка,
   треки якорей, автопроверки. Старый монтаж ещё работает, но дубль уже чистый.
2. **Композиция в браузере.** Паритет со старым монтажом плюс мокап-рамка. Хайлайты
   пересобираются той же композицией; правила отбора моментов не меняются.
3. **Раскадровка как данные.** Длительности выводятся, эффекты приходят от режиссёра,
   `storyboard.json` заменяет `scenario.json`.
4. **Студия.** Три точки контроля, дорожки эффектов, перегенерация по комментариям.

## Что не входит

- Публикация и интеграции отправки — отдельной спекой.
- Миграция существующих проектов: `mc-медиа` и `takt-как-это-работает` пересниматься
  заново по новой цепочке, старые файлы остаются как есть и открываются только на просмотр.
- Озвучка не меняется.
- Вертикальный формат хайлайтов не меняется.
- Remotion выводится из поставки на стадии 2: удаляются `optionalDependencies`, пункт
  реестра `zoom`, проверка в `doctor` и упоминания в README. `src/` остаётся в репозитории
  как референс до конца стадии 2, затем удаляется.

## Риски

**Устойчивость привода на длинных роликах — высокий, не проверен.** Прототип снимал
90 кадров, настоящий ролик это около 3000. Память, утечки и потеря кадров под нагрузкой —
именно то, на что Remotion потратил годы. Смягчение: композиция пишется портируемой, её
номер кадра приходит извне. Если свой привод не выдержит, откат — это вернуть Remotion
в зависимости и написать второй привод поверх той же композиции: день работы, а не
переписывание. Поэтому `src/` и удаляется только в конце стадии 2, когда привод проверен
на полном ролике.

**Ложные срабатывания проверки «скачок содержимого» — средний.** Легитимная смена экрана
выглядит так же, как сбой. Смягчение: проверка знает границы планов и запланированные
склейки, порог настраивается на цели съёмки.

**Качество режиссёрского промпта кодом не гарантируется — средний.** Потребуется итерация
на живых роликах. Смягчение: сюжет и раскадровка — отдельные файлы под правку человеком,
поэтому плохой прогон не блокирует работу.
