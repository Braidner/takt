# Стадия 3: раскадровка как данные — план внедрения

> **Для исполнителя:** шаги помечены чекбоксами. Каждая задача заканчивается
> самостоятельно проверяемым результатом и своим коммитом.

**Цель:** `storyboard.json` заменяет `scenario.json`. Длительность плана выводится из
его содержания, а не назначается человеком; камера, склейки и наложения становятся
данными — эффектами, которые режиссёр порождает, а человек правит.

**Архитектура:** три новых чистых модуля рядом с композицией. `storyboard.mjs` — схема,
нормализация и миграция старого сценария. `duration.mjs` — вывод длительности.
`director.mjs` — автоэффекты по состоянию. `film.mjs` перестаёт решать, как ехать камере:
он читает готовые эффекты. Съёмка исполняет типизированный план вместо массива действий.

**Стек:** Node 22, `node:test`, Playwright 1.62, системный ffmpeg. Зависимость по-прежнему
одна — playwright.

## Глобальные ограничения

- Новых зависимостей нет.
- `studio/compose/*.mjs` — без импортов Node: их грузит и браузер, и тесты.
- Формат данных на диске один: `storyboard.json`. `scenario.json` читается только
  миграцией и после неё не пишется никогда.
- Ни одного места, где длительность назначается вручную и молча: ручное значение
  помечается `source: "manual"` и пересчётом не затирается.
- Границы плана 3,5–9 с. Меньше — добирается удержанием; больше — замечание
  режиссёру, а не молчаливая обрезка.
- Комментарии, сообщения и коммиты — по-русски, в стиле репозитория.
- Каждая задача — свой коммит.

## Формат `storyboard.json`

```json
{
  "title": "Mission Control — Медиа",
  "task": "исходная задача словами — источник перегенерации",
  "status": "ready",
  "plans": [
    {
      "id": "p04", "n": 4, "at": 22.4,
      "intent": "поиск находит за пару букв",
      "title": { "text": "Нашлось за пару букв", "style": "lower" },
      "mode": "static",
      "screen": { "route": "discover", "waitFor": "text=В тренде сейчас" },
      "action": { "kind": "type", "selector": "input[placeholder*=\"Поиск\"]",
                  "text": "одиссея", "press": "Enter" },
      "duration": { "source": "derived", "seconds": 5.2 },
      "diagram": null,
      "state": "pending", "error": null, "fix": null, "took": null
    }
  ],
  "effects": [
    { "id": "e4c", "plan": "p04", "kind": "camera",
      "at": { "from": 0.6, "to": 3.1 },
      "anchor": "input[placeholder*=\"Поиск\"]",
      "params": { "move": "push", "depth": 1.26 }, "source": "auto" }
  ]
}
```

**`at` эффекта — от начала своего плана, а не от начала ролика.** Спека приводит
абсолютные времена, но у неё же длительности выводятся: любой пересчёт сдвинул бы
все абсолютные метки, и правка одного плана молча ломала бы эффекты остальных.
Абсолютное время считается сложением и показывается в студии.

`action.kind` — закрытый список: `click`, `type`, `scroll`, `hold`, `goto`.

## Карта файлов

```
studio/compose/duration.mjs    вывод длительности плана           (чистый, тесты)
studio/compose/storyboard.mjs  схема, нормализация, миграция      (чистый, тесты)
studio/compose/director.mjs    автоэффекты: камера и склейки      (чистый, тесты)
studio/compose/film.mjs        плёнка из раскадровки и эффектов   (переписан)
studio/storyboard.mjs          CLI: отправить раскадровку         (заменяет scenario.mjs)
studio/server.mjs              /api/storyboard, миграция при чтении
studio/shoot.mjs               исполняет план, а не массив действий
studio/live.js, index.html     дорожка эффектов, правка длительности
references/storyboard.md       формат для агента (заменяет scenario.md)
```

**Интерфейсы:** `planDuration(plan) → { seconds, source: 'derived', over: boolean }`;

### Задача 2: схема раскадровки и миграция

**Файлы:** создать `studio/compose/storyboard.mjs`, `test/storyboard.test.mjs`.

**Интерфейсы:**
- `normalizeStoryboard(sb) → sb` — проставляет `id` (`p01`…), `n`, `at` (сумма
  длительностей), `duration` через `planDuration`, `state` по умолчанию; считает
  `seconds` и `fps` всей раскадровки.
- `fromScenario(scenario) → storyboard` — миграция: `{goto}` → `screen.route`,
  `expect`/`{waitFor}` → `screen.waitFor`, `{click}` → `action.click`,
  `{type}` → `action.type`, `{scroll}`/`{press: PageDown}` → `action.scroll`,
  `{wait}` → `action.hold`, `label` → `title.text`, `hint` → `intent`.
- `checkStoryboard(sb) → issues[]` — план длиннее 9 с; план без титра; переход
  без `screen.waitFor`; неизвестный `action.kind`.

- [ ] Тесты на миграцию реального шага mc-медиа, на нормализацию и на проверки.
- [ ] Реализация, тесты зелёные, коммит.

### Задача 3: режиссёр — эффекты как данные

**Файлы:** создать `studio/compose/director.mjs`, `test/director.test.mjs`;
изменить `studio/compose/film.mjs` (убрать `planCamera`).

**Интерфейсы:** `autoEffects(plan, state, { last }) → Effect[]` — камера из содержания
(`push` при якоре, `pan` при длинной странице, иначе `drift`) и `transition: dissolve`
на границе, кроме последнего плана. `source: 'auto'`; эффекты с `source: 'manual'`
режиссёр не трогает.

- [ ] Тесты: те же правила камеры, что были в `planCamera`, плюс склейка и сохранение
      ручных эффектов.
- [ ] Реализация, тесты зелёные, коммит.

### Задача 4: плёнка из раскадровки

**Файлы:** изменить `studio/compose/film.mjs`, `test/film.test.mjs`,
`studio/compose/player.js`.

`buildFilm(manifest, storyboard)` берёт длительности из `plan.duration.seconds`,
камеру — из эффектов (`effects` раскадровки или `autoEffects`, если их нет), якорь

в координаты.

### Задача 5: сервер знает раскадровку

**Файлы:** изменить `studio/server.mjs`.

`GET/POST /api/storyboard`; `readStoryboard()` мигрирует `scenario.json` при первом
чтении и пишет `storyboard.json` рядом; `/api/step` пишет состояние в план;
`/api/scenario` остаётся только на чтение и отдаёт раскадровку в старой форме, пока
её читает композиция плеера — нет, плеер переводится в задаче 4, поэтому маршрут
удаляется вместе с ним.

- [ ] Реализация, ручная проверка `curl`, коммит.
