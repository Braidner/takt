# Стадия 1: съёмка состояний — план внедрения

**Цель:** съёмка перестаёт писать поток и начинает снимать состояния. Из одного снимка
страницы композиция потом собирает прокрутку, наезд и удержание.

**Архитектура:** чистые функции в `studio/lib/*.mjs` под тестами, `shoot.mjs` — оркестратор.

**Стек:** Node 22, встроенный `node:test`, Playwright 1.62, системный ffmpeg. Новых
зависимостей нет.

## Глобальные ограничения

- Новых зависимостей нет, тесты на `node:test`.
- Снимок состояния: `deviceScaleFactor: 2`, `fullPage: true`, JPEG q92.
- Липкие и закреплённые элементы скрываются `visibility: hidden` — место в потоке обязано
  сохраниться, иначе вёрстка съедет. Проверено: высота страницы не изменилась.
- Порог «крупного» липкого элемента: шире 40 и выше 20 CSS-пикселей.
- Комментарии и сообщения — по-русски.
- Каждая задача — свой коммит.

## Что уже проверено на живом стенде

- Снимок всей страницы: 2880×8278 за 224 мс, 1,2 МБ.
- Липких элементов на Mission Control два: шапка 1440×49 и боковая панель 76×762, оба
  `position: sticky`.
- В снимке всей страницы липкие видны **только сверху** — на глубине 2400 px их уже нет.
  Панорама без разделения слоёв уехала бы вместе с шапкой, а в жизни она остаётся.
- При `visibility: hidden` высота страницы не меняется: 4139 CSS-пикселей до и после.

`stickyBands(items, viewport) → Array<{edge, x, y, w, h}>`

- [ ] Тест: `stickyBands` относит шапку к верхнему краю, панель — к левому.
- [ ] Тест: `hideSticky` не меняет высоту документа, `showSticky` возвращает как было.
- [ ] Реализация.
- [ ] Коммит.

### Задача 2: Снятие состояния

**Файлы:** создать `studio/lib/state.mjs`, `test/state.test.mjs`

**Потребляет:** `waitUntilSettled` (задача сделана ранее), `findSticky`/`hideSticky`.

**Интерфейс:**
`captureState(page, { id, dir, waitFor, anchors }) → Promise<State>` где
`State = { id, body, layer, size, viewport, scale, sticky, anchors, settle }`.

Порядок внутри, и он существенный:
1. `waitUntilSettled` — экран должен успокоиться;
2. прогон прокрутки до низа и обратно — ленивые картинки обязаны догрузиться ДО снимка,
   иначе в панораме будут пустые места;
3. снова `waitUntilSettled`;
4. снимок слоя: вьюпорт сверху страницы, липкие видны;
5. `hideSticky`, снимок тела `fullPage`, `showSticky`;
6. прямоугольники якорей — в координатах снимка тела.

- [ ] Тест: на странице выше вьюпорта возвращаются два файла, размер тела больше вьюпорта,
      слой равен вьюпорту.
- [ ] Тест: ленивая картинка, догружающаяся при прокрутке, присутствует в снимке тела.
- [ ] Тест: якорь ниже сгиба попадает в `anchors` с координатами в шкале тела.
- [ ] Реализация.
- [ ] Коммит.

### Задача 3: Автопроверки состояния

**Файлы:** изменить `studio/lib/inspect.mjs`, `test/inspect.test.mjs`

**Интерфейс:** `checkStates(states, opts) → Issue[]`; сохраняются прежние

Проверки: ожидание не сошлось; якорь не попал в снимок; тело подозрительно короткое
(страница не догрузилась); слой липких пуст, хотя липкие найдены.

- [ ] Тесты на каждую, чистыми функциями над данными состояний.
- [ ] Реализация.
- [ ] Коммит.

### Задача 4: `shoot.mjs` снимает состояния

**Файлы:** изменить `studio/shoot.mjs`

- План получает `mode`: `static` по умолчанию, `live` — прежняя запись `recordVideo`.
- Для статичного плана после действий вызывается `captureState`, результат копится
  в `states[]`, файлы ложатся в `states/` проекта.
- `take.json` заменяется на `states.json`: манифест состояний плюс отчёт проверок.
- Живые планы пишутся `recordVideo` 1440×810 и помечаются в манифесте.

- [ ] Реализация.
- [ ] Прогон на стенде: `states.json` создан, файлы на месте, замечаний по якорям нет.
- [ ] Коммит.

## Самопроверка плана

Покрытие спеки: раздел «Съёмка» покрыт задачами 1, 2, 4; автопроверки — задачей 3;
липкие слои — задачей 1, и это прямой ответ на риск, названный в спеке.

Не входит: композиция панорамы (стадия 2), раскадровка (стадия 3), студия (стадия 4).

Согласованность: `findSticky` из задачи 1 используется в задаче 2; `State` из задачи 2 —
в задаче 3; обе — в задаче 4.
