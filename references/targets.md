# Цели: знание о снимаемой системе

Цель — это система, про которую снимают ролики. Заводится один раз, служит всем роликам
про неё. Живёт в `$TAKT_HOME/targets/<slug>/`:

- `target.json` — машинное: адрес, вход, признак готовности, разведанные селекторы;
- `target.md` — человеческое: заметки прозой, которые в схему не уложить.

## Завести цель

Разведай интерфейс, потом запиши разом — адрес, признак готовности, найденные селекторы:

```bash
TOKEN=$(curl -s localhost:4173/api/hello | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s -X POST "localhost:4173/api/targets?token=$TOKEN" -H 'Content-Type: application/json' -d '{
  "slug": "mission-control", "name": "Mission Control",
  "url": "https://mc.example.org/", "ready": "#root header", "user": "admin",
  "selectors": { "главная": "text=Погода", "система": "text=Виртуальные машины" },
  "note": "Разделы: /, /media, /system, /settings"
}'
curl -s -X POST "localhost:4173/api/targets?token=$TOKEN" -H 'Content-Type: application/json' \
  -d '{"use":"mission-control"}'     # привязать текущий ролик к цели
```

Пароль **не вписывай сам** — его вводит человек в форме подключения студии (клик по чипу
стенда). Наружу он не отдаётся никогда: API возвращает только признак «задан».

## Признак готовности — на нём легче всего ошибиться

`ready` — селектор, по которому видно, что интерфейс загрузился. Ошибка здесь коварна:
вход проходит, страница живая, а проверка стенда говорит «интерфейс не загрузился», и
непонятно, что чинить.

Определяется одной командой в консоли страницы после входа:

```js
[...document.body.children].map(e => e.tagName + (e.id ? '#' + e.id : ''))
```

Бери **реальный корень приложения**, а не то, что кажется типичным. `#app` и `#root` —
разные вещи; у одной системы работает первый, у другой второй.

## Разведка селекторов

Порядок такой: `takt probe` даёт общую картину — пункты меню, заголовки,
кнопки, скриншот. Дальше — точечная разведка нужного экрана.

**Классы часто бесполезны.** У приложений на Tailwind классы между разделами
неразличимы — там сотни утилитарных классов и ни одного смыслового. В таких системах
проверки веди по тексту (`text=Виртуальные машины`), предварительно убедившись, что текст
на странице один:

```js
await page.locator('text=Виртуальные машины').count()   // должно быть 1
```

Верхний регистр в макете обычно даёт CSS (`text-transform`), а `textContent` остаётся
исходным — селектор по тексту это переживает.

## Заметки: что писать в target.md

Пиши то, что нельзя вывести из `target.json` и что сэкономит время в следующий раз:

- **чего нельзя касаться** — «кнопки Стоп/Рестарт у контейнеров не нажимать, живой Proxmox»;
- **что медленно** — «раздел отчётов рисуется 5 с, шагу нужна пауза побольше»;
- **где грабли** — «списки виртуализованы, до нижних строк нужна прокрутка»;
- **особенности входа** — «после логина показывает баннер, его надо закрыть».

Дописывай **сразу**, тем же ходом, а не в конце работы: до конца работы ты можешь не
дожить в пределах этого контекста.

```bash
curl -s -X POST "localhost:4173/api/targets?token=$TOKEN" -H 'Content-Type: application/json' \
  -d '{"note":"После входа всплывает баннер с новостями — закрывать .banner-close"}'
```

Дата ставится сама. Это важнее, чем кажется: заметка без даты через полгода неотличима
от заметки, которая устарела вместе с интерфейсом.

## Несколько систем

Каждая — своя цель. Проект (ролик) ссылается на цель полем `target`, и адрес со входом
берутся оттуда. Новый ролик наследует цель предыдущего: чаще всего снимают следующий сюжет
про ту же систему.

Без этого переключение проекта оставляло бы прежний адрес — и второй ролик снимался бы не
про то, что заявлено в его названии.
