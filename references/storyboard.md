# Раскадровка: из задачи словами в планы съёмки

Человек описывает ролик обычными словами. Твоя работа — превратить это в планы, которые
можно снять, и показать черновиком: раскадровка правится до съёмки, потому что после
она стоит минут.

## Формат

```json
{
  "title": "Обзор системы",
  "task": "исходная задача словами",
  "plans": [{
    "intent": "видно, что виртуалки и контейнеры в одном списке",
    "title": "Виртуальные машины и контейнеры",
    "screen": { "route": "system", "waitFor": "text=Виртуальные машины" },
    "action": { "kind": "hold", "seconds": 3 }
  }]
}
```

- `title` — **титр для зрителя**: «Маршрут на очередь заказов», а не «проверяем таблицу».
  Это то, что появится в кадре;
- `intent` — зачем этот план в ролике. Видно только в студии; по нему же человек пишет
  замечания, а ты потом пересобираешь раскадровку;
- `screen.route` — куда попасть. `""` — корень, `null` — остаёмся на текущем экране;
- `screen.waitFor` — селектор, по которому видно, что экран **действительно** тот;
- `action` — одно типизированное действие, закрытый список из пяти видов;
- `mode` — `static` (по умолчанию) или `live`, если содержание плана в самом движении
  интерфейса. Один живой план переводит весь ролик в 25 кадров, поэтому без нужды не ставь.

## Заставка и финал

Обе карточки — записи раскадровки, а не побочный эффект того, что у ролика есть
название:

```json
"slate": { "on": true, "text": null, "subtitle": null, "seconds": 2.6 },
"end":   { "on": true, "text": null, "url": "mission-control.ru", "seconds": 2.2 }
```

Не заполняй `text` копией названия: `null` означает «взять у ролика», и обложка
поедет за переименованием сама. Свой текст ставь, когда он **отличается** от
названия — например, когда название техническое, а обложке нужна человеческая фраза.

Подзаголовок обложки, если его не задать, берётся из задачи, пока та короче 90 знаков.
Ссылка бывает только у финала, подзаголовок — только у обложки.

Карточки независимы: продуктовый ролик для сайта начинается с обложки, а короткий
ответ на вопрос в переписке — сразу с дела, но плашкой со ссылкой заканчивается.
Длительность меньше 0.4 с не принимается: такая карточка успевает только мигнуть.

Отправка:

```bash
takt storyboard draft.json          # черновиком, человек правит
takt storyboard draft.json --ready  # утверждённой (обычно это делает человек кнопкой)
```

## Действия

| `kind` | Поля | Когда |
|---|---|---|
| `click` | `selector`, `press?` | нажать на элемент |
| `type` | `selector`, `text`, `press?` | набрать текст в поле |
| `scroll` | `distance`, `speed?` | проехать по странице, если это и есть содержание |
| `hold` | `seconds` | подержать экран: план, где нужно просто дать посмотреть |
| `goto` | — | план и есть переход, на экране больше ничего не происходит |

Действие одно на план, и это не ограничение формата, а смысл: из него выводится
длительность, строится наезд камеры и рисуется курсор. План из четырёх команд подряд
не даёт ответить, что здесь показывают, — и его надо разбить.

Прокрутку **перед** кликом писать не нужно: Playwright сам доводит страницу до элемента,
а состояние снимается страницей целиком.

## Длительность не назначается

Её считает конвейер: подводка камеры плюс само действие плюс удержание результата.
Клик — 0,2 с, набор — по длине текста, прокрутка — по дистанции, `hold` — сколько
сказано. План не короче 3,5 с и не длиннее 9; вылез за девять — раскадровка скажет об
этом, и такой план надо разбить надвое.

Поэтому поля `seconds` у плана нет. Если человек хочет своё время — он ставит его в
студии, и оно помечается ручным.

## waitFor — не перестраховка

Клик по пункту меню, который раскрывает подменю вместо перехода, проходит без ошибки:
элемент найден, клик выполнен, план «успешен». А в кадре остался прежний экран. Ролик
снимется целиком и покажет не то, что обещают титры, — и заметишь ты это на
смонтированном результате, то есть после всей съёмки.

Поэтому план, который меняет экран, обязан назвать признак, по которому это видно.

## Ритм

- **Один экран — один план.** Пересъёмка отдельного плана дешевле пересъёмки сцены;
- **План без действия — пауза на экране.** Так снимаются места, где ничего не
  происходит, но зрителю нужно успеть прочитать: это `hold`;
- **Титр живёт от начала своего плана до конца.** Мигающие титры означают, что планы
  идут слишком плотно, — значит, их надо укрупнить.

## Эффекты

Камеру, склейки и наложения ставит режиссёр — сам, по содержанию плана: есть цель у
действия, значит наезд; длинная страница — панорама; иначе дрейф. Присылать их в
черновике не нужно.

Человек правит эффекты в студии, и его правка помечается ручной. **Ручные эффекты при
перегенерации не трогай**: скопируй их в новую раскадровку как есть.

## Что не должно попадать в раскадровку

Ты снимаешь чужую живую систему. Необратимое — удаление, отправка сообщения, платёж,
остановка сервиса — в раскадровку не идёт, даже если человек описал это словами. Скажи
об этом прямо и предложи безопасный аналог: набрать текст, не отправляя; открыть форму,
не подтверждая.

Печать в поле без отправки — нормальный демонстрационный приём и ничего не создаёт.

## Правка раскадровки (`scenario_note`)

Человек описывает, что хочет изменить. Различай по стоимости:

- **титр, длительность, порядок, удаление плана, параметры эффекта** — это данные,
  человек знает их лучше тебя, и правит их сам в студии, без тебя;
- **«добавь план, где показано X»** — требует знания интерфейса, это твоя работа:
  разведай, найди селекторы, добавь план, отправь обновлённую раскадровку черновиком.
